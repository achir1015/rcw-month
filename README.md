## 系統結構

把整個系統想成一棟「醫院大樓」：

- **大樓大門**：Firebase 帳號登入（Email＋密碼）。沒有帳號進不了大樓。
- **單位辦公室**：公司＋部門（例如「臺北市立聯合醫院忠孝院區／呼吸照護病房」）。每間辦公室有自己的門鎖，也就是「管理者密碼」。
- **班表櫃子**：每間辦公室裡各有「護理師」「病房助理」兩個櫃子，櫃子裡放著每個月的班表。

```
Firebase 帳號登入
└─ 公司（例：臺北市立聯合醫院忠孝院區）
   └─ 部門（例：呼吸照護病房）　← 管理者密碼
      ├─ 護理師　 ─ 各年月班表
      └─ 病房助理 ─ 各年月班表
```

各單位的班表資料完全分開，進入 A 單位看不到 B 單位的資料。

## 使用流程

1. 開啟網址，用 **Email 帳號＋密碼** 登入。
2. 出現「**選擇單位**」畫面：從下拉選單選擇公司／部門，輸入該單位的 **管理者密碼**，按「進入」。
3. 進入後，畫面上方會顯示公司名稱與部門名稱。
4. 點選「**護理師**」或「**病房助理**」，即可查詢、編輯，或匯入 PDF／Excel 班表。
5. 要換到別的單位：按右上角「**切換單位**」。要結束使用：按「**登出**」。

### 新增／編輯公司與部門

1. 在「選擇單位」畫面，點下方「**管理公司／部門**」。
2. 輸入**任一單位**的管理者密碼解鎖。
3. 可以：
   - 「＋ 新增單位」：輸入公司名稱、部門名稱、管理者密碼。
   - 「編輯」：修改公司名稱、部門名稱；密碼欄留空表示不修改密碼。
   - 「刪除」：移除該單位（雲端上該單位的班表資料不會一起刪除）。原始單位「呼吸照護病房」不可刪除。

### 預設單位

| 公司名稱 | 部門名稱 | 初始管理者密碼 |
|---|---|---|
| 臺北市立聯合醫院忠孝院區 | 呼吸照護病房 | `Aa123456` |

> 建議第一次使用後，到「管理公司／部門」→「編輯」修改成新密碼。

## 月班表管理系統 — 完整功能總結

### 一、查詢與顯示

-   依「護理師 / 病房助理」分類查詢，輸入民國年＋月份自動換算西元年
-   全員班表：Excel 風格凍結窗格——上下捲動時「員編/姓名/日期」標題固定在上方；左右捲動時「員編/姓名」欄固定在左邊
-   點擊姓名 → 展開個人月曆式班表，可切換「每週起始星期」重新排版；標題旁有「上一筆／下一筆」按鈕可直接切換到前後一位員工
-   **直接編輯班別代碼**：在全員班表點擊任一位員工任一天的儲存格即可就地修改，Enter 或點別處＝確定（自動存檔＋統計列即時重新計算），Esc＝取消不存檔
-   全站字體放大25%、表格支援雙向捲動，手機使用友善

### 二、統計功能

-   **團體統計**（表格最下方，固定貼在捲動範圍底部）：逐日統計 D白班／E小夜／N大夜人數，並加一列「合計」＝當天總上班人數（粗體黑字放大15%）
-   **個人統計**（個人月曆下方）：統計該員工整月 D白班／E小夜／N大夜／OFF休假各幾天
-   分類規則：依代碼內容判斷（含 D、白值→白班；含 E→小夜；含 N、夜8→大夜；含 off/OFF/國/休/例→休假）

### 三、資料匯入

-   **PDF 匯入**：自行解析文字座標畫出表格，處理過表頭拆行、姓名跨行、日期資料誤判年月等實際問題
-   同時支援三種PDF版面並會自動偵測：「日期橫向排表頭(9/1格式)」的一般版面、「列印成PDF」常見日期直向排列的轉置版面，以及日期用純數字(1~31、無月份)表頭、且表格旁有簽名欄/請假統計/上月末日參考欄等額外內容的版面；會自動排除這些非班別資料的欄位，避免姓名或班別被污染
-   若PDF內文沒有年月／類別文字（例如轉置版面常見此狀況），會自動退而改用檔名辨識（例如「115年10月護理師班表.pdf」）
-   **Excel 匯入**：PDF 為掃描圖檔時的備援管道（先用外部OCR工具轉檔）
-   匯入規則：同單位＋同類別＋年＋月若已有資料，會提示後才整批覆蓋
-   匯入的資料只會存進**目前所在的單位**

### 四、資料儲存與備份

-   儲存於 **Firebase Firestore** 雲端資料庫，跨裝置/瀏覽器資料同步（單位清單也存在雲端，換電腦一樣看得到）
-   支援匯出／匯入 **XML 備份檔**，可搬家或留存
    -   匯出只包含**目前單位**的資料，檔名含部門名稱，例如 `月班表備份_呼吸照護病房_20261028.xml`
    -   XML 根節點帶有單位資訊：`<scheduleSystem company="…" department="…">`
    -   匯入別的單位的備份檔時，會先跳出提醒，確認後才匯入到目前單位

### 五、安全性

-   **Firebase Authentication** 登入畫面，未登入無法使用系統
-   每個單位另有**管理者密碼**；雲端只存密碼的 SHA-256 雜湊值，不存明碼
-   Firestore 安全性規則要求登入才能讀寫

### 六、其他

-   自訂「班」字圖示，支援手機「加入主畫面」捷徑

## 雲端資料結構（Firestore）

| 集合 | 文件 ID | 內容 |
|---|---|---|
| `orgs` | `default`（原始單位）／`org…`（新增單位） | `company`、`department`、`passwordHash` |
| `schedules` | 原始單位：`nurse-2026-10`、`assistant-2026-10` | 沿用舊格式，既有資料不需搬移 |
| `schedules` | 新增單位：`{單位ID}__nurse-2026-10` | 另帶 `orgId` 欄位，標記所屬單位 |

### Firestore 安全性規則

`orgs` 集合也需要允許已登入使用者讀寫。若規則只開放 `schedules`，新增單位時會出現「單位設定寫入雲端失敗」，請改為：

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /schedules/{doc} {
      allow read, write: if request.auth != null;
    }
    match /orgs/{doc} {
      allow read, write: if request.auth != null;
    }
  }
}
```
